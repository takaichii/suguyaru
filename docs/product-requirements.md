# プロダクト要求定義書

## プロダクトビジョンと目的

**サービス名：** スグヤル  
**コンセプト：** 未来を、今の行動に。

「今日やるタスクを自分で選ぶこと」に特化したシンプルなタスク管理アプリ。

タスク管理ツールの多くは機能が豊富すぎるために、何をすべきかの判断をツール自体に委ねてしまう。スグヤルは逆の発想で、ユーザーが毎日 **意識的に「今日やること」を選ぶ行為そのもの** を価値とする。

---

## ターゲットユーザーと課題・ニーズ

### ターゲットユーザー

- 日々タスクを抱えているが、何から手をつければよいか迷いやすい個人
- 複雑なタスク管理ツールに疲れ、シンプルなものを求めているエンジニア・学習者
- 目標（Goal）に紐づいた行動を習慣化したい人

### 課題・ニーズ

| 課題 | ニーズ |
|------|--------|
| タスクが多すぎて今日やることが見えない | 今日やることだけを表示したい |
| 「なんとなく」タスクをこなしてしまう | 意識的に今日のタスクを選ぶ習慣をつけたい |
| 複雑なツールの設定・操作に時間をとられる | 余計な操作なくすぐ使い始めたい |
| タスクが目標とつながっていない | 目標と行動を紐づけて管理したい |

---

## 主要な機能一覧

| 機能 | 概要 |
|------|------|
| Goal 管理 | 目標の作成・一覧表示 |
| Task 管理 | Goal に紐づくタスクの作成・一覧表示 |
| Today 選択 | 未完了タスクから最大5件を Today に追加 |
| Today 画面 | 選んだタスクのみ表示・チェックで完了 |

---

## 成功の定義

MVP として以下の状態を成功とする。

- ユーザーが Goal を作成し、Task を紐づけて管理できる
- 毎日「今日やるタスク」を自分で選んで Today 画面で完了チェックできる
- ページリロード後もデータが失われない
- 迷わず操作できる（主要な操作が3ステップ以内）

---

## ビジネス要件

- バックエンドなし・localStorage のみでデータ管理（インフラコスト不要）
- MVP として最小構成で実装し、将来の機能拡張の余地を残す
- 認証・課金は MVP スコープ外

---

## ユーザーストーリー

```
As a ユーザー
I want to 今日やるタスクを自分で選びたい
So that 毎日の行動を意識的に決められる

As a ユーザー
I want to タスクを Goal に紐づけて管理したい
So that 何のためのタスクか明確にできる

As a ユーザー
I want to 選んだタスクだけを Today 画面で確認したい
So that 余計な情報に惑わされず集中できる

As a ユーザー
I want to タスクを完了チェックしたい
So that 今日の進捗を確認できる
```

## 受け入れ条件

### Goal 管理
- [ ] Goal を作成できる
- [ ] 作成した Goal が一覧に表示される

### Task 管理
- [ ] Goal を選択して Task を作成できる
- [ ] 作成した Task が Goal ごとにグループ表示される
- [ ] Goal が存在しない場合、Task 作成フォームに警告が表示される

### Today 選択
- [ ] 未完了の Task 一覧が Goal ごとにグループ表示される
- [ ] チェックで Task を Today に選択できる
- [ ] 最大5件を超えて選択できない
- [ ] すでに Today 追加済みの Task はチェック済みで表示される
- [ ] チェックを外すと Today から除外される

### Today 画面
- [ ] 今日選択した Task だけが表示される
- [ ] タスク行のチェックで isDone をトグルできる
- [ ] 完了したタスクは打ち消し線 + グレーで表示される
- [ ] 「+ タスクを選ぶ」ボタンから選択画面に遷移できる

### データ永続化
- [ ] ページリロード後もデータが維持される

## 機能要件

### FR-01：Goal 管理
- Goal はタイトルのみ持つ
- Goal のタイトルは空文字禁止・最大100文字
- Goal は複数作成可能
- Goal の削除・編集は MVP スコープ外

### FR-02：Task 管理
- Task は必ず1つの Goal に紐づく
- Task のタイトルは空文字禁止・最大100文字
- Task は未完了（isDone: false）/ 完了（isDone: true）の状態を持つ
- Task の削除・編集は MVP スコープ外

### FR-03：Today 選択
- Today に選択できる Task は1日あたり最大5件
- 選択対象は未完了タスクのみ（isDone: false）
- Today の選択情報は日付と taskId のペアで保持する
- 今日日付（YYYY-MM-DD）の TodayTask のみ Today 画面に表示する

### FR-04：Today 完了チェック
- Today 画面のチェックボックスで Task の isDone をトグルできる
- 完了した Task は Today 画面に引き続き表示する（非表示にしない）

---

## 非機能要件

### NFR-01：データ永続化
- すべての状態（Goal / Task / TodayTask）は localStorage に永続化する
- ページリロード後もデータが失われないこと

### NFR-02：パフォーマンス
- ページ遷移・操作のレスポンスは体感上即時であること
- データ量が少量（Goal 数十件、Task 数百件）の範囲では劣化しないこと

### NFR-03：UI/UX
- Neo Terminal テーマ（ダーク・monospace・ターミナル風）を統一して適用すること
- 主要な操作（Today にタスクを追加して完了する）が3ステップ以内で完了すること
- モバイルブラウザでも最低限操作できるレスポンシブ対応

### NFR-04：セキュリティ
- ユーザー入力はすべて XSS 対策（React のエスケープに依存）
- localStorage に機密情報は保存しない（本アプリは個人用途のためリスク低）

### NFR-05：保守性
- TypeScript の型定義を徹底し、型エラーゼロの状態を維持する
- コンポーネントは単一責任を保ち、再利用可能な単位に分割する
